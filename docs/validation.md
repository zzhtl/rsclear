# 验证记录

验证日期：2026-11-03。环境：Ubuntu 24.04.1 x86_64，Rust/Cargo 1.99.1，8 vCPU（Xeon Gold 6230R 虚拟机）、约 16 GiB 内存，项目位于 `/dev/sda2`。未执行系统级缓存清空或修改内核页缓存；机器同时存在其他工作负载，以下为本机观测值，不是跨设备性能承诺。

以下保留首次本机验收记录；之后的 GitHub CI 验证结果见末节。

## 功能与构建

- `cargo test --locked --all-features`：14 个常规测试通过；2 个依赖额外环境的测试默认忽略，并已在本次单独执行通过，总计验证 16 个测试。
- `cargo clippy --locked --all-targets --all-features -- -D warnings`、`cargo fmt --check`：通过。
- 实际 Cargo 项目：普通项目、自定义 target、包含两个成员的 workspace、独立 build 目录；清理后源码和 Cargo.lock 保留，普通项目能够重新构建。
- 实际文件系统：隐藏文件、非 UTF-8 路径、重叠扫描根、循环符号链接、硬链接、稀疏文件、权限拒绝、内容变化、根目录被替换、取消及不跟随链接的递归清理。
- Linux 废纸篓：通过隔离 XDG 数据目录执行真实移入和恢复，恢复后内容一致。
- 跨文件系统：在项目内部挂载 8 MiB tmpfs；实测同名跳过、自动编号、内容/权限/扩展属性保留。复制 16 MiB 非零数据触发真实 ENOSPC，源文件完整、目标正式文件不存在、临时副本移除。测试结束后已卸载。
- 运行中的百万文件扫描：收到真实扫描进度后取消，178 ms 内完成退出，无工作线程滞留。

## 百万文件负载

使用 `rsclear-bench` 生成真实文件，每个文件 16 字节；分目录场景为 1000 个目录，每目录 1000 个文件，单目录场景为同一目录下 100 万文件。所有运行均得到 100 万文件、零错误，以下采用最终扫描实现。

| 场景 | 元数据线程 | 扫描耗时 | 吞吐（文件/秒） | 峰值 RSS |
|---|---:|---:|---:|---:|
| 分目录 | 1 | 69.391 s | 14,411 | 23,324 KiB |
| 分目录 | 4 | 22.459 s | 44,526 | 23,860 KiB |
| 单目录 | 4 | 29.798 s | 33,559 | 24,228 KiB |

这些运行没有人为清空页缓存，先后顺序及共享机器 I/O 会影响结果；不能把两次耗时之比直接当作纯线程加速比。

初版为每个路径维护多个大型 B-tree 索引，且同一目录内的元数据读取串行，单目录表现明显较慢。最终实现采用顺序记录、紧凑排序索引、目录 inode 去重，以及独立的有界元数据线程池；同一目录也能并行读取。每次扫描重建可丢弃索引，避免逐条删除旧索引。

## 桌面验收

在项目内准备 Xvfb，通过 X11 实际启动 release 应用，使用真实百万文件目录扫描。中文、扫描进度、分页列表和操作入口已截图检查。

- 完整桌面进程峰值 RSS：195,208 KiB（约 190.6 MiB），低于 512 MiB 目标。
- 扫描结果：1,000,000 文件，扫描用时 15.418 s；该次页缓存较热，不能与上表直接比较。
- 431 个 UI 调用的 CPU 耗时 P95：0.978 ms；此指标包含界面构建时间，不等于 GPU 呈现时间或端到端输入延迟。
- 使用虚拟显示器的软件渲染路径，启动时有 DRI3 不可用提示；窗口正常显示并退出，未据此宣称硬件 GPU、Wayland 或 macOS Metal 已实测。

截图及原始性能输出保留在本地 `.build/smoke`、`.build/benchmark`，不纳入 Git。验收后清理本次生成的百万文件测试目录，避免占用工作磁盘；基准命令可重新生成同样的数据。

## 打包与未验证项

Linux release GUI 和权限辅助程序已实际构建，生成 `dist/rsclear_0.1.0_amd64.deb` 和 `dist/rsclear-0.1.0-linux-x86_64.tar.gz`，包内二进制与 release 构建内容一致。当前 Ubuntu 构建产物需要 glibc 2.39；打包脚本根据二进制符号自动填写 deb 依赖，不能将这个本地产物称为 Debian 12 兼容包。CI 使用 Debian 12 构建以提供较低 glibc 基线，但 CI 尚未远端执行。

macOS ARM64 的应用包、签名和可选公证脚本，以及 ARM64 CI 作业已提供；本机没有 macOS SDK 或 Mac，尚未执行 macOS 构建/实机验证。macOS ACL、原生废纸篓、管理员授权、隐私权限及 Metal 需要在 Mac 验收。

本机未安装 npm/pnpm/Homebrew，相关工具命令未做本机集成清理验证；路径会在运行时重新确认，pnpm 的版本化 store 还会验证固定路径参数的解析结果。未对宿主机执行 APT、journal 或系统临时目录清理。特权请求的版本、字段、路径边界、平台限制及保留时间已通过测试；真实 polkit/AppleScript 管理员交互及系统清理效果仍需隔离系统环境验收。取消特权任务时，已经启动的管理员命令可能需要等待结束；不能保证普通用户能够强制终止该命令。

不把静态扫描视为一致性快照，不保证清理时外部程序完全停止修改文件。清理失败和部分完成会逐项报告；废纸篓、永久删除、移动和系统命令的结果分别显示。

## 启动时创建桌面快捷方式

新增 3 项常规测试与 1 项桌面集成测试，均通过。验证重复创建不会修改已有文件或断开的链接，支持中文、空格及引号等路径，拒绝无法表达的路径；使用真实 `desktop-file-validate` 和 GIO 启动生成的入口，确认特殊字符未被当作命令或占位符执行。macOS 裸二进制启动包装的脚本也通过实际执行验证，但 Finder 行为仍需 Mac 实机验收。

在项目内配置隔离的中文“桌面”目录，通过虚拟显示器连续启动 release 二进制两次：首次自动生成 `rsclear.desktop`，Exec 指向当前二进制绝对路径，权限为 `0755`；第二次启动后内容与修改时间均未变化。原始输出保留在 `.build/shortcut-smoke`。Linux 无法自动设置信任标记时显示“允许启动”提示，创建失败不会中断应用。

变更后的常规检查：17 个测试通过，3 个需特定环境的测试默认忽略；其中本次新增的 GIO 集成测试已单独运行通过。Clippy、格式检查与 release 构建通过，Linux deb 和便携包同步更新。

## GitHub CI 发布验证

[发布前验证工作流](https://github.com/zzhtl/rsclear/actions/runs/41630314238) 已在 Debian 12 x86_64 与 macOS 14 ARM64 通过格式检查、Clippy、常规测试和打包步骤。Linux 还通过真实 X11 窗口及启动自动创建桌面快捷方式的冒烟测试；两端构建附件均已上传。

CI 验证补齐了 Linux X11 必需的动态运行库。macOS 的稀疏文件改用系统 `COPYFILE_DATA_SPARSE` 拷贝实际空洞区间，保留独立内容校验；同一回归用例的源文件与落盘后的副本均保持 4 KiB 占用。新增零块/有效数据交替和跨缓冲区边界的回归用例。文件名测试按平台实际约束构造：Linux 覆盖非 UTF-8 原始字节，macOS 覆盖可创建的 Unicode 文件名。

`v*` 标签须与 Cargo 包版本一致。只有两端检查、打包和校验全部成功，CI 才发布包含 deb、tar.gz、macOS app.zip、dmg 及两个 SHA-256 校验文件的 Release；下载入口见 README。macOS 使用 ad-hoc 签名，未进行 Developer ID 公证。CI 构建和文件操作测试不替代最终用户桌面的权限对话框与现场清理验收。
